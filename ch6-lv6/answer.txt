【チケット #3021】単一テーブル検索の最適化

設問１.EXPLAIN の type 列が ALL になっています。これは何を意味しますか？
またパフォーマンスにどのような影響がありますか？

回答：
type が ALL は、「フルテーブルスキャン（全件検索）」を意味します。

今回は members テーブルの 120万件すべて を読み込み、メールアドレスが一致するかを1件ずつ確認しています。

そのため、
・検索に時間がかかる
・ディスクへのアクセスが増える
・CPUに負荷がかかる
・本番環境ではタイムアウトの原因になる、という問題があります。


設問２.possible_keys が NULL になっている理由を説明してください。

回答：possible_keys は、「このSQLで利用できるインデックス」を表します。
NULL は、利用できるインデックスがないことを意味します。
そのため、MySQL はインデックス検索ができず、120万件すべてを検索しています。


設問３.このSQLを改善するための ALTER 文または CREATE INDEX 文を記述してください。

回答：

CREATE INDEX idx_email
ON members(email);

または

ALTER TABLE members
ADD INDEX idx_email (email);


設問４.インデックス追加後、EXPLAIN の各列（type・possible_keys・key・rows・Extra）がどのように変わるかを予測してください。

回答：
・type
ALL → const

メールアドレスは1件しか存在しないため、1件だけ取得します。

・possible_keys
NULL → idx_email

利用できるインデックスとして表示されます。

・key
NULL → idx_email

実際に使用されたインデックスです。

・rows
1200000 → 1

120万件ではなく、1件だけ検索します。

・Extra
Using where → （空欄）

インデックスだけで目的のデータを取得できるため、余分な処理はありません。

email 列にインデックスを追加後、検索対象は120万件から1件だけになり、検索速度が大幅に変わります。
